Network forensics: DDoS and malware traffic

Two packet capture investigations: finding the attacker in an HTTP flood, and recovering a file that was pretending to be something else.

Type
RMIT coursework (Computer and Internet Forensics). Investigation 1 individual, investigation 2 split with a teammate
Year
2026
Tools
Wireshark, Kali Linux, xxd, file, sha256sum, VirusTotal

Investigation 1: HTTP flood

Problem. A web server was flooded with HTTP requests. The capture contained a lot of traffic, and the job was to separate the attack from normal activity and identify where it came from.

  1. Get an overview. Used Statistics, Protocol Hierarchy to see which protocols made up the traffic.
  2. Find the noisy host. Used Statistics, Conversations to see which hosts were exchanging the most packets with the server.
  3. Narrow it down. Applied display filters to isolate the HTTP requests and confirm the attacking host’s behaviour.

Investigation 2: disguised malware file

Problem. A file was downloaded over HTTP, and its name suggested a harmless file type. The job was to recover it and find out what it really was.

  1. Find the transfer. Used Follow HTTP Stream to read the request and response.
  2. Recover the file. Exported it with File, Export Objects, HTTP.
  3. Check its real type. Looked at the first bytes with xxd and ran file. The file signature (magic bytes) shows the true type, whatever the extension says.
  4. Hash and look it up. Calculated a SHA-256 hash with sha256sum and searched for that hash on VirusTotal, instead of opening the file. All of this was done inside a Kali Linux VM.

Findings

Both investigations reached a clear answer: the flood was traced to its source host, and the downloaded file’s real type didn’t match its name.

Specific hosts, file names and hashes are left out because this was assessed coursework.

Recommendations

  • Rate-limit requests per client and put a web application firewall or DDoS protection in front of public web servers.
  • Block or inspect downloads based on real file type, not just the extension.
  • Add confirmed malicious hashes and sources to blocklists, and search other machines for the same hash.

What I learned

  • Statistics views are the fastest way to get oriented before scrolling through packets.
  • File extensions can’t be trusted. Magic bytes can.
  • Looking up a hash is safer than uploading or opening a suspicious file.
